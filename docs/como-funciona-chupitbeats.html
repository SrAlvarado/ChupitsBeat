Cómo funciona ChupitBeats
Una radio que escribe su propia música

ChupitBeats no reproduce nada grabado. Cada tema se compone, se escribe como un programa de Strudel y se evalúa en vivo en el navegador. Detrás suena un escenario 3D con estética PlayStation 1 que cambia con la emisora. Este documento explica cómo está montado por dentro: la cadena que va de una etiqueta de ambiente a un patrón sonando, las tres emisoras, el truco del look PS1 y las trampas que costó descubrir.

01La idea: música como código, no como fichero

Una radio normal tiene una lista de canciones. ChupitBeats tiene un compositor. Cuando pulsas play, el programa inventa una tonalidad, una progresión de acordes, un motivo melódico y un patrón de batería; después traduce todo eso a un programa de Strudel —texto, código de verdad— y se lo da al motor para que lo ejecute.

La consecuencia interesante es que el resultado es legible. El panel "Código" de la interfaz no es una decoración: es literalmente el tema que está sonando. Puedes editarlo, pulsar Ctrl+Enter y la radio obedece tu versión al instante.

El proyecto nació como recreación de k-lofi.vercel.app. Al abrir su bundle resultó que aquel no usa Strudel: es un planificador propio sobre WebAudio con voces sintetizadas a mano. ChupitBeats mantiene la idea (radio lofi generativa, sin samples de melodía) pero la expresa en Strudel, y de ahí sale el panel de live coding que el original no tiene.

02El motor: Strudel

Strudel es el puerto a JavaScript de TidalCycles, el lenguaje de patrones para live coding musical. Su unidad no es la nota sino el ciclo: describes qué pasa dentro de un compás y el motor lo repite, lo subdivide y lo combina. 

$: s("[bd <hh oh>]*2").bank("tr909").dec(.4)

Esa línea significa: dos veces por ciclo, un bombo y —alternando en cada repetición— un charles cerrado o abierto, con los sonidos de una TR-909 y decaimiento corto. ChupitBeats genera líneas así, pero calculadas.

Por qué generar texto y no construir objetos

Strudel expone una API de JavaScript con la que se pueden construir patrones programáticamente. Aquí se eligió lo contrario: generar código como cadena y pasarlo por evaluate(). Cuesta un poco más de cuidado, pero da tres cosas que la API no da:

Transparencia

Lo que suena se puede leer. No hay una capa intermedia que traducir mentalmente.

Edición en vivo

El oyente puede reescribir el tema sobre la marcha. Es una radio y un editor a la vez.

El DJ escribe igual

Cuando compone la IA, produce exactamente el mismo artefacto: un programa de Strudel.

Paso 1 — De etiquetas a números

Los seis chips de ambiente no son decorativos: cada uno desplaza un perfil. "Onírico" sube el eco y la reverb y baja el sesgo menor; "somnoliento" baja la densidad melódica, la energía de la batería y el brillo; "concentrado" hace lo contrario con la batería. Se pueden combinar, y sus efectos se suman. 

case 'onírico':
  p.echo += 0.22; p.reverb += 0.12; p.minorBias -= 0.25
  p.brightness += 150; w.arpegio += 0.3
  break

Paso 2 — La ficha del tema

Con ese perfil se sortea un tema concreto. La tonalidad sale de un rango MIDI, el modo (mayor o menor) se decide con el sesgo acumulado, y la progresión se elige de un repertorio de cuatro progresiones menores y tres mayores con acordes de séptima y novena — el vocabulario del jazz que sostiene el lofi.

Paso 3 — La traducción

strudelize.ts convierte la ficha en texto. Los acordes se calculan como voicings sin fundamental (la lleva el bajo) plegados al registro medio, y se escriben como nombres de nota. La rejilla de 16 semicorcheas se imprime en mini-notación, agrupada de cuatro en cuatro para que se lea como un compás. 

// ✳ ChupitBeats — «cristal a las 3am»
// LOFI · lluvia + acogedor · 74 bpm · BB menor · 24 compases

setcpm(74/4)

// acordes
$: note("<[db4,f4,ab4] [bb3,db4,eb4,f4,gb4] [c4,f4,ab4]>")
  .struct("x ~ ~ ~  ~ ~ ~ ~  ~ ~ x ~  ~ ~ ~ ~")
  .sound("sine")
  .attack(.012).decay(.34).sustain(0.22).release(0.7)
  .lpf(2465).lpq(1.6)
  .vib(.4).vibmod(0.037)
  .room(0.27).roomsize(2.6)
  .gain(.48).pan(.44)
  .analyze(1)
El detalle del tempo

Strudel piensa en ciclos por minuto, no en pulsos. Como un ciclo equivale a un compás de cuatro negras, la conversión es setcpm(bpm/4). De ahí sale también la duración del tema: compases × (60/bpm) × 4 segundos.

Paso 4 — La antena

radio.ts mantiene el hilo de la emisión. Evalúa el programa, calcula cuánto dura, y programa el corte: al terminar llama a hush(), deja 2,2 segundos de silencio —el respiro entre cortes de una emisora de verdad— y compone el siguiente. Cambiar de emisora o pulsar "Otra toma" adelanta ese ciclo sin romper el reloj.

04Las tres emisoras

El mismo material armónico se escribe de tres formas distintas. No es un filtro sobre el mismo patrón: cada género genera capas diferentes.

EmisoraTempoEscenarioCapas que escribe
LOFI 60–92 · 74 Habitación de estudio Acordes de piano eléctrico, bajo escaso, melodía pentatónica, batería con swing
HOUSE 112–132 · 124 Playa al atardecer Bombo a negras, palmas al 2 y 4, charles a contratiempo, bajo de corcheas, stabs
SCHRANZ 140–172 · 152 Callejón pintado Bombo distorsionado, percusión rodante, línea ácida, drone grave

El acompañamiento del lofi

Sólo la emisora lofi tiene estilos de acompañamiento, sorteados con pesos que las etiquetas de ambiente modifican: clásico (el acorde entero al principio del compás), balada (notas sostenidas, caja sustituida por aro), comping (respuestas sincopadas) y arpegio.

La línea ácida del schranz

El acid no se escribe nota a nota: se deja que una señal continua barra el filtro. El corte va modulado por ruido de Perlin lento y la resonancia sube con el dial de textura. 

.lpf(perlin.range(280, 4200).slow(11)).lpq(18)
.shape(0.5)

05Lo que deliberadamente no es Strudel

La lluvia y el crujido de vinilo no son patrones. Son texturas continuas, y meterlas en un motor de eventos rítmicos sería forzar la herramienta. Viven en ambience.ts, en WebAudio puro, colgadas del mismo AudioContext que usa Strudel — con lo que comparten reloj y salida.

Lluvia

Dos capas de ruido: una manta grave con paso bajo a 900 Hz y una banda de gotas en 3.100 Hz, más un LFO a 0,07 Hz que hace respirar al chaparrón.

Vinilo

Un búfer generado con ruido muy bajo y chasquidos esporádicos (probabilidad 0,0011 por muestra), filtrado en banda a 2.400 Hz.

El dial de ambiente los sube y baja, pero atenuado según la emisora: en la playa suena a la mitad y en la nave industrial a un cuarto, porque allí la calle pinta menos.

06El look PlayStation 1: cuatro trucos, cero modelos

Los escenarios no usan modelos importados: son cajas, planos y cilindros. La estética no viene de la geometría sino del pipeline.

01
Render a 320×180 Se dibuja a resolución de consola y se escala con filtro nearest
WebGLRenderTarget
02
Temblor de vértices Los vértices se ajustan a una rejilla en espacio de recorte
onBeforeCompile
03
Iluminación plana MeshLambert y texturas de canvas sin filtrar ni mipmaps
NearestFilter
04
Pasada final Ojo de pez, aberración cromática, color de 15 bits, grano y viñeta
ShaderMaterial

El truco número dos es el que más carácter aporta. La PS1 no tenía coma flotante en la transformación de vértices, así que las cosas vibraban. Se reproduce inyectando tres líneas en el shader de cualquier material: 

vec2 grid = vec2(uJitter, uJitter * 0.5625);
gl_Position.xy = floor(gl_Position.xy / gl_Position.w * grid)
                 / grid * gl_Position.w;

Y la cuantización de color a 15 bits, en la pasada final, es una sola línea:

c = floor(c * 32.0) / 32.0;   // 32 niveles por canal
El ojo de pez

Es distorsión de barril sobre las UV, y no es fija: se abre con la energía de la música. En schranz llega casi al doble que en lofi, junto con el temblor de cámara. La imagen se pone nerviosa cuando la música lo hace.

07Los escenarios, y Claudy

Cada emisora tiene su escena. Se construyen la primera vez que se piden y se guardan, así que cambiar de emisora en caliente es instantáneo.

Habitación · lofi

Ventana con lluvia instanciada, ciudad al fondo con ventanas que se apagan, escritorio, portátil que late con la música, gato en el alféizar y guirnalda.

Playa · house

Cielo de atardecer con degradado por shader, mar de malla animada con normales recalculadas, hoguera, torres de altavoces que respiran y espuma que va y viene.

Callejón · schranz

Muros con grafitis generados en canvas, contenedores pintados, valla, escalera de incendios, aire acondicionado con ventilador y carteles que parpadean.

Grafitis dibujados en tiempo de ejecución

No hay ni una textura descargada. Los muros se pintan con <canvas>: primero hormigón moteado, encima throw-ups (burbujas con contorno y chorretones), después tags —garabatos hechos con curvas cuadráticas y una rúbrica final hacia arriba— y pegatinas giradas al azar. Cada muro es distinto en cada carga.

Claudy

La mascota aparece en los tres escenarios: cuerpo naranja, dos orejillas, dos ojos oscuros y cuatro patas. Flota, gira despacio y patalea con la energía del audio. En el callejón lleva además un bote de espray que suelta pintura al ritmo.

Cómo la imagen escucha

Cada capa del programa Strudel termina en .analyze(1), que engancha un analizador compartido. La interfaz lo lee con getAnalyzerData('frequency', 1), y de ahí salen dos cosas: las 20 barras del visualizador —lo único con color en toda la consola— y una energía media suavizada que mueve la escena.

08El DJ: cuando escribe la IA

El botón "Componer con IA" llama a /api/dj, una función serverless que pide a un modelo el programa de Strudel completo —no una descripción, no parámetros: el código— junto con un título y una frase de presentación.

El prompt del sistema le enseña las reglas del motor: qué sonidos existen, qué efectos son válidos, que cada capa debe terminar en .analyze(1) y cómo suena cada emisora. La respuesta viene forzada a un esquema JSON.

Variable de entornoProveedorModelo por defectoSe cambia con
ANTHROPIC_API_KEYClaudeclaude-opus-5—
XAI_API_KEYGrokgrok-4.6XAI_MODEL
GEMINI_API_KEYGeminigemini-3.7-flashGEMINI_MODEL

xAI y Gemini exponen endpoints compatibles con OpenAI, así que comparten un único fetch parametrizado por URL, clave y modelo. Claude va por su SDK oficial. Y hay dos capas de resistencia:

Cadena de proveedores

Se recorren todos los que tengan clave. Si uno falla por saldo o credenciales, se prueba el siguiente. Una variable olvidada en el entorno ya no deja la radio sin DJ.

Reintento sin esquema

Si la capa de structured outputs falla, se repite pidiendo JSON a secas con la forma descrita en el prompt. Un parser tolerante desenvuelve incluso el JSON en bloque markdown.

Sin clave también funciona

El DJ es un extra. Sin ninguna variable configurada la radio sigue emitiendo: el compositor local escribe los temas y el botón devuelve un aviso legible.

Decisión de diseño de la interfaz

La consola es deliberadamente neutra: grises, bordes de un píxel, tipografía de sistema, sin rotaciones ni sombras duras. El único elemento con color es el visualizador. Todo lo demás cede el protagonismo al escenario 3D.

10Cinco trampas que costó descubrir

Ninguna de estas aparece en la documentación con un cartel luminoso. Todas costaron una sesión de depuración.

1 · initStrudel() no carga los worklets

Inicializar Strudel no basta: los AudioWorklets de superdough se cargan aparte. Sin await initAudio() después, efectos como .coarse() o .vib() fallan con un error de construcción de nodo que no menciona los worklets por ninguna parte.

2 · .arp() toma índices, no nombres de modo

En Strudel 1.3, .arp("up") no arpegia hacia arriba: intenta indexar el acorde con la cadena "up", obtiene undefined y revienta la consulta. Hay que pasarle números: .arp("0 1 2 3 2 1").

3 · No todas las cajas de ritmos tienen los mismos sonidos

bd, sd, hh y oh existen siempre, pero rim y cp no están en RhythmAce, y rim tampoco en AkaiLinn. Pedir uno que falta deja la capa muda. Un helper elige el primero que esa caja tenga de verdad.

4 · Vercel interpreta export default como handler de Node

En la carpeta /api, un export default function(req) se toma como el handler clásico (req, res), así que req.json() revienta sólo en producción — en local el endpoint ni se ejecuta. La forma correcta es el export por método: export async function POST(req: Request).

5 · Un temporizador de cliente demasiado corto

El abortador del navegador cortaba a los 30 segundos y el error que salía era "signal is aborted without reason", que parece un fallo del proveedor y no lo es. Los modelos que razonan tardan más que eso en escribir un tema entero.

Y una que no es un fallo

Al desplegar, una pestaña abierta desde antes sigue ejecutando el JavaScript viejo mientras sus peticiones van a la función nueva. Da síntomas imposibles: interfaz antigua con errores modernos. Se arregla recargando.

11Trabajar con el proyecto

npm install
npm run dev        # servidor de desarrollo
npm run build      # tsc + comprobación de api/ + empaquetado
npm run snap       # captura y auditoría con Playwright

El script de captura

snap.mjs es la herramienta de iteración visual: abre la página, elige emisora, pulsa play, encadena temas y reporta cualquier error de consola. Es lo que detecta cuando un patrón generado no compila o falta un sonido. 

URL=http://localhost:5173/ GENRE=schranz RETUNES=2 npm run snap

Despliegue

El proyecto está en la raíz del repositorio, así que Vercel detecta Vite sin configuración. La única variable necesaria es la clave del proveedor de IA, y sólo para el botón del DJ.

Cambiar una variable no basta

Vercel congela las variables de entorno en el despliegue. Después de añadir o borrar una hay que redesplegar para que la función la vea.
